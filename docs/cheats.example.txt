# Cheat file template for the DCB PC port. Copy it to cheats/<serial>.txt next to settings.ini
# (the current directory or the executable's folder), e.g. cheats/SLPS-03101.txt, or point
# DCB_CHEATS=<file> at it. F4 in game opens the trainer: toggle cheats, reload this file, search
# memory and freeze what you find (S saves the list back here, comments kept).
#
# A cheat is a name in brackets, "on" or "off", then PS1 GameShark / Action Replay code lines:
#   80aaaaaa vvvv   write 16-bit       30aaaaaa 00vv   write 8-bit
#   10aaaaaa vvvv   add (16-bit)       11aaaaaa vvvv   subtract (16-bit)
#   20aaaaaa 00vv   add (8-bit)        21aaaaaa 00vv   subtract (8-bit)
#   D0/D1/D2/D3aaaaaa vvvv   run the next line only if the 16-bit value is ==, !=, <, > vvvv
#   E0/E1/E2/E3aaaaaa 00vv   the same for an 8-bit value
#   C0aaaaaa vvvv   run the rest of this cheat only if the 16-bit value == vvvv
#   5000nnss iiii   repeat the next 80/30 line nn times, address +ss and value +iiii each time
# Addresses are 80000000-801FFFFF (main RAM). Enabled cheats are applied once per frame.
# Not supported (the cheat is rejected with a message): C1, C2, D4, D5, D6, 1F and anything else.
# Comments start with '#' or ';' (also after a code line).

# --- Found by memory search, UNVERIFIED --------------------------------------------------------
# 800DF1E8 is a 32-bit counter inside the loaded save data (RAM 800DEFC4 holds the save image;
# playtime_tick 80014E24 increments it, docs/re/save-data.md)
# that the game increments every frame, both in menus and in the field; probably the play-time
# counter shown on the load screen. Found with the trainer's search engine on RAM dumps of a
# scripted run ("increased" filter over six snapshots); holding it was checked headless (the game
# increments it, the cheat puts it back every frame), its meaning was not.
[Play time counter held at 0 (unverified)] off
800DF1E8 0000
800DF1EA 0000

# Digi parts: one bit per part at 800DF200-800DF20F, parts 0-126 (the starters give 0, 10

[All Digi parts] off
